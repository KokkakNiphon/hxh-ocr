# Blog data files

Generated by `scripts/blog/make_assets.py` (do not edit by hand; re-run the script).

## glyphs.json

Geometry of every Hunter × Hunter base glyph, for drawing them in JS (SVG or canvas). Exported from
`rust/hxh-synth/assets/glyphs.json` (which `scripts/export_glyphs.py` writes from `hxh_ocr/glyphs.py`);
the script checks every point and every mark position against `hxh_ocr/glyphs.py`.
`glyph_test.svg` is drawn from this file alone, with the same layout as `previews/glyph_sheet.png`.

**Units.** Em. Each form is centred on its own bounding box (so its `bbox` is symmetric about 0),
x to the right, **y down**. Glyphs keep their relative sizes from the chart (い is a lone dot, て is
short), so draw every glyph at the same em size; do not normalise each one to its box.
`stroke_width_em` (0.071875) is the chart's stroke width.

```jsonc
{
  "units": "...", "stroke_width_em": 0.071875,
  "order": ["あ", "い", ..., "ん", "ー"],          // 47 base glyphs, gojūon order, ー last
  "rows": [{ "consonant": "k", "kana": ["か","き","く","け","こ"] }, ...],
                                                   // gojūon table; null = empty cell (や row, わ row)
  "glyphs": {
    "ま": {
      "romaji": "ma",
      "pos": [6, 0],                               // [row in `rows`, column a/i/u/e/o]
      "forms": [                                   // forms[0] is the default (the main form)
        { "name": "left-pointing (Ƹ)", "source": "...", "default": true, "weight": 0.85,
          "bbox": [x0, y0, x1, y1],
          "strokes": [
            { "type": "line", "pts": [[x, y], ...], "closed": false },
            { "type": "dot",  "c": [x, y], "r": 0.19 }
          ] },
        { "name": "right-pointing (Σ)", "default": false, "weight": 0.15, ... }
      ]
    }, ...
  },
  "marks": { "dakuten":    { "dx": 0.21, "dy": -0.07, "r": 0.065, "hollow": false, "width_scale": 1.0 },
             "handakuten": { "dx": 0.24, "dy": -0.09, "r": 0.095, "hollow": true,  "width_scale": 0.65 } },
  "mark_rule": { ... the rule below, as text ... },
  "composed": { "が": { "base": "か", "mark": "dakuten", "romaji": "ga" }, ..., "ぱ": { "base": "は", "mark": "handakuten" } },
  "vocab": [...],                                  // the readers' 74 tokens (73 kana + space)
  "small_to_full": { "ぁ": "あ", ... }             // small kana share the full-size glyph
}
```

**Strokes.** `line`: a polyline (arcs, circles and splines are already flattened), drawn with
width `stroke_width_em`, round caps and joins; `closed: true` joins the last point to the first
(え, ね, rings such as お and the も ring). `dot`: a filled disc of radius `max(r, stroke_width / 2)`.

**Forms.** Only three glyphs have more than one, all with `weight` = how often the generator draws
each form:
- ま: left-pointing Ƹ (default, 0.85, as in both official charts) and the fan chart's Σ (0.15);
- せ: wide (default, 0.5, Hunterpedia and the printed guidebook) and narrow "4" (0.5, 2011 anime);
- も: filled dot (default, 0.5) and hollow ring (0.5, 2011 anime and Omniglot).

**Voiced kana.** A composed kana is its base glyph plus a mark at the lower right:

```js
const m = data.marks[c.mark], [x0, y0, x1, y1] = form.bbox, s = 1;   // s = mark scale
const cx = x1 + m.dx * s, cy = y1 + m.dy * s, r = m.r * s;          // y1 is the bottom (y down)
// dakuten: filled disc, radius max(r, sw / 2)
// handakuten: ring, radius max(r, sw * m.width_scale), line width sw * m.width_scale
```

`bbox` is the stroke geometry only (line points, dot centre ± r), not the stroke width. Use the bbox
of the form actually drawn: the narrow せ puts ぜ's dot closer. The training generator (v4) also
jitters the mark: sideways to 0.55-1.35 × dx (never closer than stroke_width / 2 + mark radius +
0.03 em) and vertically by U(−0.06, 0.03) em.

## charts.json

```jsonc
{
  "curves": [ { "id", "title", "x": "step", "y", "unit", "note", "source", "entry", "file",
                "series": [ { "id", "label", "file": "runs/<run>/log.csv",
                              "points": [[step, value], ...],        // the plotted metric
                              "acc" | "precision" | "recall": [[step, value], ...] } ] } ],
  "tables": [ { "id", "title", "unit", "source", "entry", "file", "note",
                "columns": [ { "key", "label", "unit"? } ],
                "rows": [ { <key>: value, ... } ] } ]        // null = not reported
}
```

Percentages are plain numbers (`1.16` means 1.16 %); F1 in `detector_int8` and some
`detector_full_val` rows are fractions as in the journal (see each column's `unit`). `source` is the
journal heading a table sits under and `entry` the dated entry containing it
(`docs/research/JOURNAL.md`). Curves are every logged evaluation (30 points for the readers, 18 for
the detector). The one table not from the journal is `confidence_filter`: its 0.85 row is the result
recorded in `web/models/det.json`, the full sweep was measured with `web/test/page_e2e.mjs
--conf-sweep` (its 0 row reproduces the final detector's journal numbers: F1 91.0 %, CER h 9.2 %,
v 18.2 %).
